## Candidate changes and verification

The shared transport now also serves math, vocabulary and the Kokugo history
adapter. Kokugo retains its baseline capture, exact legacy event fingerprint,
enrollment token retry and pre-registration queueing. Another subject registering
first does not bypass Kokugo baseline capture. Legacy pending seeds are retained.

Legacy-database copying is shared upstream. It preserves the old database, checks
school/endpoint ownership before copying credentials, refuses conflicting records,
verifies destination writes before marking completion, and exposes a sanitized
blocking reason. A legacy credential without endpoint evidence is not transferable.

Only acknowledged batch members are removed. Partial/malformed replies, retryable
errors and offline restart preserve the outbox. Explicit sync waits for ongoing
work before refreshing control. Hash manifests use portable forward-slash paths.

Initial verification: 59 Cloud assertions; isolated Worker runtime; four actual
subject adapters in Chromium at 390px/touch and 1280px, concurrent registration,
baseline fingerprints, offline/restart/5xx/partial/malformed response recovery,
ignored/revoked state and raw-data exclusion. Existing subject regressions are
being run separately; this evidence is not an all-subject CLEAN declaration.

`scripts/cross-subject-browser.mjs` expects sibling WaseShibu repository checkouts,
math build dependencies, and `PLAYWRIGHT_MODULE` / optional `CHROMIUM_PATH`.
